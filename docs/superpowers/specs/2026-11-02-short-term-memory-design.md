# yeRAG 短期记忆改造设计

状态：**已实施到工作区，未提交、未部署**。日期：2026-11-02。

本次实现与验证见 [交付记录](../../verification/2026-11-02-short-term-memory.md)。

本设计依据用户确认的融合方案整理。代码核对基线为分支 `agent`，HEAD `4898c48269e88cc05487fe71f4eaf5e9fb838364`。下文保留原设计契约和实施前差异；实际验证范围及未验证项以交付记录为准。

目标体验：**近期直接记得，早期知道去哪里查，原始记录由用户决定何时删除。**

原始问答长期保存；近期原文与滚动摘要自动进入上下文；旧细节通过工具找回；摘要在达到阈值时同步生成。长期 Markdown 记忆保持现有设计，继续异步提取。

## 1. 机制来源与范围

以下是方案选定的机制借鉴关系，不是对上游当前版本或默认配置的核验记录。

| 借鉴来源 | 采用机制 |
| --- | --- |
| LangMem | 模型调用前检查历史大小，按需生成滚动摘要并保留近期消息 |
| Letta | 历史退出上下文后，Agent 仍可搜索原始对话 |
| Pi | 压缩结果与原始历史分开保存，通过明确边界重建上下文 |

第一版历史找回使用 MySQL，不新增向量索引，不使用 Elasticsearch 召回个人记忆。本文的预算是 yeRAG 的配置选择。

## 2. 存储、保留与会话身份

| 内容 | 保存方式与生命周期 |
| --- | --- |
| 原始问题、完整答案 | MySQL 持久保存，默认不自动过期 |
| 滚动摘要、覆盖位置、摘要版本 | MySQL 保存，随会话保留 |
| 近期上下文缓存 | Redis，TTL 为 7 天，失效后从 MySQL 重建 |
| 原始记录删除 | 用户删除会话时清理对应记录、摘要和缓存 |
| 活跃请求、后台任务 | 保留现有状态管理与故障清理 |

会话空闲、缓存过期、历史压缩均不能触发原始问答删除。会话使用业务 `conversationId`，不能使用 WebSocket 连接 ID 代替会话或持久用户身份。

用户可以恢复旧会话继续交流。新建会话由用户显式操作，空闲时间不再决定自动更换会话。前端恢复旧会话后必须允许发送，并继续使用所选会话的 `conversationId`。

删除会话必须同时撤销关联执行和任务的写入资格。删除前已开始的摘要、回答完成、缓存刷新和长期提取，即使迟到，也不能重新创建或写入该会话。

已被旧清理逻辑清空的历史无法通过本次迁移恢复；迁移只能保留现存数据。现有到期字段的迁移处理、删除屏障及数据库约束需要在实施时一并落地。

## 3. 上下文预算

| 参数 | 确定值 |
| --- | --- |
| 历史摘要触发阈值 | 16,384 tokens |
| 压缩后的历史目标 | 8,192 tokens |
| 摘要最大预算 | 2,048 tokens |
| 压缩后近期原文预算 | 6,144 tokens |

上述预算只控制摘要和历史问答。当前问题、系统提示、长期记忆、检索证据、工具定义和工具结果分别计量，实际模型请求发送前统一检查总输入预算，并预留输出空间和协议开销。

使用与配置模型相匹配的 tokenizer；字节和记录数量上限只作为资源保护，不能替代 token 预算。历史从压缩后的约 8k 增长至 16k，再触发下一次压缩，避免每轮反复总结。低于或等于阈值时不因固定轮数提前触发摘要。

## 4. 一次问答流程

1. 接收请求：验证认证用户、会话归属、`requestId` 幂等以及当前会话是否存在执行中的回合。
2. 读取历史：取得当前摘要及其覆盖位置之后的已完成问答。SQL 单页满载时通过游标继续读取，不能把 `LIMIT 200` 当作历史终点。
3. 检查历史预算：不超过 16,384 tokens 时直接使用；超过时在调用 Agent 前同步压缩。
4. 调用 Agent：注入摘要、近期原文和当前问题，执行现有工具循环，保留现有 WebSocket 事件协议。
5. 提交结果：完整回答先保存到 MySQL，再发送完成事件。取消、失败的半截回答不能标为已完成。
6. 后续处理：刷新缓存，创建并执行长期 Markdown 记忆提取任务。长期提取仍异步执行。

下一轮不能等待 Worker 才看到上一轮问答。MySQL 是权威来源，缓存尚未刷新或不可用时，版本检查必须使请求回源 MySQL。回调始终绑定原始用户、会话和回合，不能根据前端当前选中的会话写入。

## 5. 摘要生成与提交

超过阈值后，从最新完整回合向前选择约 6,144 tokens 的近期原文，其余较早内容与旧摘要共同生成新摘要。

摘要保留：

- 当前任务与目标。
- 用户明确提出的约束。
- 已确认的结论及决定。
- 已完成、未完成和受阻事项。
- 关键对象、参数及可追溯的回合 ID。

历史中的助手回答仍是历史记录，不能自动视为经过验证的事实。摘要输入中的命令、引用和工具结果不能提升为系统指令。

继续使用现有字段：

| 字段 | 职责 |
| --- | --- |
| `summary_covered_turn_seq` | 新摘要覆盖到的最后一轮位置；当前实现使用回合 ID，不能将其误当作会话内连续计数 |
| `summary_revision` | 提交时比较旧版本，防止旧摘要覆盖新结果 |

模型调用在事务外执行。生成成功并通过输出预算校验后，摘要正文、覆盖位置和版本必须在同一事务中更新，提交前比较旧版本并检查会话仍然存在且允许写入。

若新摘要覆盖至回合 80，后续上下文使用“覆盖至 80 的摘要 + 80 之后的已完成原文 + 当前问题”。摘要失败时不能推进覆盖位置；版本冲突时重新读取最新状态，不能覆盖已提交的新摘要。

单次摘要输入也必须满足模型预算。需要分批时，以完整回合和游标推进，只有实际送入模型并成功提交的内容才能推进覆盖位置。不得把截断或未读取的内容标记为已经摘要。

## 6. 历史原文工具

注册两个只读 `AgentTool`：

| 工具 | 行为 |
| --- | --- |
| `search_conversation_history` | 关键词搜索当前会话，返回片段、时间、角色及回合 ID |
| `read_conversation_turns` | 读取指定回合和少量相邻回合，支持分段续读 |

服务端注入认证用户和当前会话，模型只提供查询词、回合 ID 及有界的分页/续读参数。工具不能接受模型指定的用户、组织、ACL 或其他会话身份。

每次搜索与读取都校验会话所有权和删除状态；查询必须限定当前用户、当前会话及已完成回合。指定其他会话的回合 ID 不能绕过边界。返回记录数及序列化后的 token 总量均设硬上限，截断时返回明确标记和可继续读取的位置。

典型行为：

- “我们之前决定了什么？”优先使用已有摘要。
- “之前那段 Lua 的第二个条件是什么？”先搜索历史，再读取原文回答。

工具结果作为不可信历史数据处理。历史助手回答不能作为企业知识库的权威证据。历史工具在各来源模式中的可见性和调用链上下文传递，需要在实施时明确，不能通过历史找回绕过当前来源限制。

## 7. 异常与边界

| 场景 | 确定行为 |
| --- | --- |
| 摘要超时或失败 | 保留旧摘要，携带预算内近期原文，提示上下文缩减 |
| 单轮历史特别长 | 保留有截断标记的片段及回合引用，通过工具续读 |
| Redis 不可用或被清空 | 从 MySQL 恢复 |
| 摘要版本冲突 | 重新读取最新状态，不覆盖 |
| 用户取消生成 | 不将半截回答标为已完成 |
| SQL 单页达到上限 | 使用游标继续读取 |
| 用户删除会话 | 停止关联任务，阻止迟到任务访问或恢复会话 |

短期摘要从 Worker 移除，统一由调用前路径负责。缓存刷新不得隐式触发摘要模型调用。长期 Markdown 记忆提取继续使用现有异步提取、服务端证据验证、租约和重试机制。

## 8. 实施前差异与实施顺序

以下为实施前、上述 HEAD 下的静态代码核对结果；表中“当前实现”指该基线，不能视为改造后现状。

| 范围 | 当前实现 | 所需改造 |
| --- | --- | --- |
| `MemoryProperties`、`MemoryStore.maintain` | 正文默认保留 7 天，到期清空问答；摘要也按会话到期时间清空 | 将持久数据保留与缓存 TTL 分开，取消自动正文/摘要清理，迁移现有到期字段 |
| `MemoryStore.currentLocked`、`begin` | 空闲或上下文到期后切换会话，拒绝向旧 `CLOSED` 会话发送 | 显式新建、恢复旧会话，使用请求所选的业务会话 |
| `MemoryContextService` | 按模型总预算或显式轮数选择历史，省略前缀时摘要 | 使用独立的 16k/8k/2k/6k 历史预算，保留最后的模型总预算检查 |
| 摘要失败路径 | 返回空的短期历史快照 | 保留旧摘要和预算内近期原文，显式标记缩减 |
| `MemoryWorker.poll` → `context.sync` | 缓存同步进入 `refresh`，可能调用摘要模型 | 缓存同步与摘要职责分开，Worker 不生成短期摘要 |
| `MemoryStore`、`ChatHandler` | 回答落库后发送完成事件；已有会话/摘要版本检查 | 沿用持久化顺序，验证下一轮不依赖 Worker |
| 摘要提交 | 已有正文、覆盖位置、版本的一条条件更新语句 | 保留原子条件更新，移除缓存到期门槛，补充删除与迟到提交屏障 |
| 历史读取 | 近期上下文已有向前游标翻页；`uncoveredHistory` 每次最多 200 轮 | 确保摘要扫描与历史工具均有完整游标语义 |
| Agent 工具上下文 | `ToolExecutionContext` 仅含用户、引用偏移和调用 ID | 传递服务器确认的当前会话，新增严格参数校验的两个历史工具 |
| `MemoryController`、聊天前端 | 有列表/历史接口；旧会话只读；没有会话删除接口 | 补齐恢复、删除接口与交互，处理缓存及任务撤销 |

建议实施顺序：

1. 持久化生命周期和会话恢复/删除：同步更新完整 DDL、增量迁移与数据库设计文档，先建立删除与迟到写入屏障。
2. 调用前历史预算、同步摘要、版本冲突处理及降级：保留现有长期 Markdown 召回，拆分 Worker 的缓存同步路径。
3. Agent 当前会话上下文和历史工具：实现 MySQL 搜索、有界读取、续读和权限隔离。
4. 前端恢复/删除会话与事件隔离：确保迟到消息仍绑定原请求，恢复旧会话后可继续交流。
5. 执行下列验收与回归，将实际命令、结果和未验证项另行记录。

## 9. 验收标准

以下为验收契约。已执行验证与仍需真实服务验证的项目见交付记录。

- 上一轮刚提出的要求，下一轮立即可用；Worker 暂停或缓存尚未刷新时仍成立。
- 历史不超过 16,384 tokens 时不提前摘要；超过后压缩，摘要不超过 2,048 tokens，近期原文按 6,144 tokens 预算选择，明确记录覆盖边界。
- 压缩后历史可重新增长，避免每轮反复摘要；所有请求仍通过模型总输入预算检查。
- 被摘要省略的代码、数字和原话可以通过工具找回，包含分段续读及跨 SQL 页边界的情况。
- Redis 清空或不可用后，仍能从 MySQL 恢复对话。
- 摘要失败不清空全部可用历史、不推进覆盖位置；版本冲突不覆盖新结果。
- 单轮历史超出预算时保留带回合引用和截断标记的片段，并可通过工具读回。
- 数月前保存的会话可以恢复继续交流；空闲或缓存到期不切换会话、不删除原文，每轮输入仍有界。
- 取消生成不保存半截完成答案；重复请求保持幂等；并发活动回合遵守现有会话约束。
- 不同用户和不同会话的历史不能互相读取，模型不能指定身份或会话绕过授权。
- 删除会话后，历史工具、正在执行的回答、摘要、缓存刷新和长期提取任务均不能继续访问或恢复该会话。
- 长期 Markdown 记忆的异步提取、证据验证、所有权和顺序保护保持有效。

验证先执行相关 Memory/Agent/工具测试，再执行 `mvn test`。涉及前端时执行 `pnpm typecheck`、`pnpm lint`、`pnpm build` 并检查 lint 修改。真实 MySQL 并发与删除竞争需要运行适用的 MySQL 测试，不能以 H2 通过代替。
